# Data sources

None of this data is vendored in git (see `.gitignore`) -- it's regenerated by
running the scripts in `scripts/`. This keeps the repo small and makes it clear
exactly where every input comes from.

| Source | Script | Local path | License / terms |
|---|---|---|---|
| Kaggle "Gaza Before and After" (`abdoomoh/gaza-before-and-after-2`) | `scripts/download_imagery.py` | `data/raw/imagery/section_N/{before,after}_<date>.png` + matching `.json` | See the Kaggle dataset page for the uploader's stated terms; imagery is Sentinel-2 L2A (ESA Copernicus, free and open). |
| Microsoft GlobalMLBuildingFootprints | `scripts/download_building_footprints.py` | `data/raw/building_footprints/gaza_buildings.geojsonl` | [CDLA Permissive 2.0](https://cdla.dev/permissive-2-0/) |
| UNOSAT Gaza Strip Comprehensive Building & Housing Unit Damage Assessment, 29 Feb 2024 edition (product 3804) | `scripts/download_unosat.py` | `data/raw/unosat/UNOSAT_GazaStrip_CDA_29Feb2024.gdb/` | UNOSAT data is released for humanitarian use; see [unosat.org/products/3804](https://unosat.org/products/3804) for current terms. UNOSAT explicitly describes this as a **preliminary, non-field-validated** product -- treat it as a weak label source, not ground truth (this is also how the paper uses it). |

Re-download everything:

```bash
python3 scripts/download_imagery.py               # ~60MB, 15 sections x before/after
python3 scripts/download_building_footprints.py   # ~100MB, all of Gaza Strip
python3 scripts/download_unosat.py                 # ~30MB zipped+extracted
```

## Notes on scope

- **Imagery**: the full Kaggle archive is ~6GB (34 sections x ~115 weekly images
  each, 2023-01 to 2025-03). `download_imagery.py` reads the remote ZIP's central
  directory over HTTP Range requests and downloads only one before-war and one
  after-war image per requested section, instead of pulling the whole archive.
  Default sections are the paper's fixed test (4, 5) and validation (10)
  sections, plus 12 more sections chosen by lowest index for training -- **this
  training subset is our own choice, not a reconstruction of the paper's
  original 12 sections** (which were selected via an overlap-auditing process
  we don't have access to; see Fig. 1 in the paper). Pass `--sections` to
  `download_imagery.py` to change the selection.
- **Building footprints**: downloaded for the whole Gaza Strip (~280k buildings,
  ~100MB) since Microsoft's partitioning doesn't go finer than that; the
  pipeline notebook clips this down to the sections/boundary actually in use.
- **UNOSAT**: this is the Feb 2024 edition cited in the paper. Later editions
  exist on HDX (e.g. 7th/8th Comprehensive Damage Assessment, through Dec 2024)
  if a more recent damage snapshot is wanted -- `download_unosat.py`'s
  `HDX_PACKAGE_API` constant can be pointed at a different HDX dataset slug.
- Reading the UNOSAT `.gdb` requires `geopandas`/`fiona` with GDAL's built-in
  `OpenFileGDB` driver (no proprietary ESRI SDK needed; `pip install geopandas`
  is enough on Colab). Its exact field schema wasn't verified ahead of time
  (no GDAL available in the environment these scripts were written in), so the
  analysis notebook discovers layer/column names at runtime rather than
  assuming specific field names.
